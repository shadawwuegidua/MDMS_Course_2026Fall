# 第一阶段需求与验收清单

本阶段开发一个基于 MongoDB 的简化在线问卷系统，完成账号、问卷创建与发布、填写、答案校验、题目跳转和统计。界面以操作清楚为准。

依据：同目录上级的《大作业一第一阶段.docx》中的“初始用户需求”及技术、测试、提交要求。

当前进度：第一阶段七个步骤已完成。下列 24 项功能已实现，并通过自动化及浏览器检查中的对应场景；结果和范围见 `测试报告.md`。

## 一 功能与验收清单

下表保留最初确定的验收标准，用于对照代码与实测结果。用户后续可按 `技术讲解与检查指南.md` 独立复查。

| 编号 | 功能 | 验收时应看到的结果 |
|---|---|---|
| U1 | 用户注册与登录 | 可以注册、登录、退出；记录用户名和注册时间；错误密码不能登录；数据库不保存明文密码。 |
| U2 | 用户权限 | 两个账号只能管理各自的问卷、查看各自问卷的统计；直接访问他人的管理或统计地址也不能获取数据。 |
| S1 | 创建问卷 | 能保存标题、说明、匿名设置、重复填写设置和可选的截止时间。 |
| S2 | 问卷列表 | 登录后能看到自己的问卷，重新打开页面后数据仍存在。 |
| S3 | 发布与分发 | 草稿发布后得到可访问的填写链接，其他账号可通过该链接进入。 |
| S4 | 截止与关闭 | 问卷可手动关闭；到达截止时间后不能继续提交；草稿不能供他人提交。 |
| Q1 | 单选题 | 可以配置题目和选项、设置必答；必答留空或提交不属于该题的选项时被拒绝。 |
| Q2 | 多选题 | 可以配置选项，限制最少、最多或恰好选择的数量；不符合数量限制的答案被拒绝。 |
| Q3 | 文本填空 | 可以限制最短和最长长度，超出限制时提示错误。 |
| Q4 | 数字填空 | 可以限制最小值、最大值、是否为整数；非数字及不符合限制的输入被拒绝。 |
| J1 | 单选跳转 | 根据所选选项进入配置的目标题目。 |
| J2 | 多选跳转 | 根据是否选中指定选项进入配置的目标题目。 |
| J3 | 数字跳转 | 根据数字比较条件进入配置的目标题目。 |
| J4 | 可配置规则 | 创建者能在页面设置规则；修改配置会改变跳转结果；未命中规则时进入下一题。 |
| R1 | 填写流程 | 填写者先登录，通过链接按顺序或跳转路径作答，完成后可以提交。 |
| R2 | 提交校验 | 网页显示错误原因；后端在保存前再次检查问卷状态、填写权限和答案是否合法。 |
| R3 | 答卷保存 | 每次成功提交形成独立记录；多人提交不会覆盖彼此的答案。 |
| R4 | 匿名填写 | 匿名问卷的答卷和统计接口不会向问卷创建者展示填写者身份。 |
| R5 | 重复填写 | 允许时同一账号可提交多份答卷；不允许时第二次提交被拒绝。 |
| T1 | 单选统计 | 显示每个选项的选择人数，以及该题的回答总人数。 |
| T2 | 多选统计 | 显示每个选项被选择的次数。 |
| T3 | 填空统计 | 可以查看文本和数字填空的全部有效填写内容。 |
| T4 | 数字平均值 | 可以查看数字填空的平均值，结果与已知测试答案一致。 |
| T5 | 统计范围 | 创建者能查看整个问卷及某一道题的统计；新增答卷后，重新查看时统计随之更新。 |

## 二 本阶段采用的实现约定

以下用于明确原文未细化的行为，是本项目的设计选择。

1. **登录与匿名**：所有填写者都需登录。“匿名”指对问卷创建者隐藏身份；系统内部保留账号关联，用于判断重复填写。填写页应说明这一点。
2. **重复填写**：创建问卷时提供开关，默认不允许同一账号重复提交。允许重复时，每次成功提交均参与统计。
3. **题目编辑**：草稿可以编辑题目和规则；发布后固定题目内容与规则，避免已有答案与题目失配。截止时间和关闭操作属于问卷管理功能。
4. **跳转方向**：只允许跳到后面的题目。单选判断选项相等，多选判断包含某个指定选项，数字支持等于、大于、大于等于、小于、小于等于。多条规则按配置顺序取第一条命中规则；没有命中则进入下一题，最后一题之后提交。
5. **实际答题路径**：提交时根据最终答案重新确定路径，只校验和保存路径上的答案；被跳过的必答题不会阻止提交，被跳过题目的残留答案不参与统计。
6. **答案限制**：题目可设必答；选填题留空时不检查长度或数值范围。多选“恰好选择 N 个”用最少和最多均为 N 表达。
7. **统计口径**：只统计成功提交且校验通过的答卷。被跳过或选填留空不算该题已回答；多选按选项计数；数字平均值只使用有效数字，无有效数字时显示“暂无数据”。
8. **保存时机**：完成提交后保存答卷，本阶段不加入自动保存草稿或断点恢复。

## 三 技术与范围约束

- 业务数据存储在 MongoDB，不使用关系数据库，不使用现成问卷系统框架。
- 采用 Python、Flask 和 PyMongo，一个后端程序配合简单网页。集合字段与校验见 `数据库设计.md` 和根目录 `schema.json`，接口见 `API说明.md`。
- 范围以初始需求为准；题库、题目共享、版本历史和跨问卷统计属于后续需求。
- 所有跳转和校验配置必须来自问卷数据，不能为某份演示问卷写死在程序里。
